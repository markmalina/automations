# Для чего Марку n8n и как он дополняет Gate

Решение владельца 06.11.2026: начать разработку, подтвердить ограниченный пилот Railway до $1; выделить отдельный репозиторий для расширяемой системы взаимодействия сервисов. Создан приватный `markmalina/automations`. Первая задача — загрузка готовых файлов из обычного Work в GitHub. Дополнительная идея владельца — будущий сервис трекинга, с которым люди взаимодействуют через Telegram. Это идея использования, а не уже разработанный продукт.

## Возможности готового n8n

n8n — движок процессов с визуальным редактором. Процесс состоит из trigger/action nodes. Триггер принимает Webhook, событие интеграции или запускается по расписанию. Дальше nodes читают/пишут данные, вызывают API, фильтруют и преобразуют значения, ветвят выполнение, ожидают условия, обрабатывают ошибки. Штатные интеграции дополняются универсальным HTTP Request. Для простой передачи и Git модель не нужна.

| Задача | Возможная роль n8n | Статус |
|---|---|---|
| Файлы Work → GitHub | Защищённый приём, проверка комплекта, запись, один commit/push, квитанция | Разработка; полная приёмка не выполнена |
| Telegram-трекинг | Событие → проверка пользователя через backend → запись → ответ | Идея владельца, не подключено |
| Синхронизация сервисов | Webhook/API → преобразование → другой API | Дальнейшее применение |
| Регулярные отчёты | Расписание → чтение данных → сборка → доставка в разрешённый канал | Дальнейшее применение |
| Длинные бизнес-процессы | Условия/ожидание/ошибки, если подходят ограничения движка | Требуется отдельный дизайн |

## Граница с Gate

Слово «гейт» уместно в бытовом смысле точки входа. n8n — более широкий оркестратор интеграций; он не автоматически заменяет API backend или полноценный API gateway. Наличие Webhook не добавляет само по себе строгую авторизацию, лимиты, атомарную идемпотентность и гарантии доставки.

Предлагаемое разделение (проектное решение, не аудит текущего кода Gate):

- Gate/прикладной backend: идентичность и права пользователя, бизнес-правила трекинга, канонические записи/состояние, специальные операции.
- n8n: соединение готовых API/сервисов, расписания, преобразования, оркестрация и наблюдаемое выполнение процессов.
- При использовании обоих n8n вызывает Gate через явный API. Не дублируем базу пользователей и бизнес-логику без обоснования.

Пример будущего трекинга: сообщение Telegram → n8n получает событие → Gate проверяет Telegram ID и право на операцию → Gate записывает событие в каноническую базу → n8n формирует ответ. Для простого бота, уже полностью покрытого Gate, дополнительный n8n может не понадобиться.

Одному Telegram-боту назначается один владелец Webhook. Нельзя переключать Webhook существующего бота с Gate на n8n без отдельного перехода: это может прекратить текущую доставку. В этом пилоте Telegram/Gate не меняются.

## Ресурсы и расширение

Один экземпляр n8n может обслуживать несколько workflows с отдельными credentials и журналами. Добавление каждого workflow не требует нового контейнера. RAM нужна и ожидающему процессу; CPU/память увеличиваются во время выполнения. Sleep-on-idle нельзя обещать до проверки фоновой активности и пробуждения. Для первого теста: один официальный image, SQLite, один постоянный диск; Redis, отдельный Postgres и платный n8n Cloud не требуются.

Рабочие пути на volume `/data`: база и ключевые настройки `/data/.n8n`; Git `/data/work/git`; временные комплекты `/data/work/uploads`; квитанции `/data/work/receipts`. Перезапуск использует тот же volume. Git-клоны можно восстановить из GitHub; база/credentials/квитанции требуют сохранения диска и постоянного encryption key. Это ещё не проверенная процедура аварийного восстановления и не замена backup.
