# Railway: установка и происхождение шаблонов

Обновление 06.11.2026, около 13:25 МСК. Пользователь разрешил установить плагин и завершить авторизацию существующего аккаунта; сообщил, что ранее соединение отваливалось каждые 2–3 часа и требовало Reconnect.

## Фактически выполнено

В карточке ChatGPT нажата «Установить плагин». После завершения вместо неё появились «Управлять» и «Попробовать в чате». В настройках Railway отображается существующая «Учётная запись пользователя Mark в Railway», Primary, используемый метод OAuth. Новая форма логина/согласия в наблюдаемом процессе не появлялась; нельзя утверждать, что выдан новый refresh token или исправлены прежние отключения.

Discovery повторно подтвердил installed=true. В текущем ходе Railway tools в реестре исполнителя ещё отсутствуют. Проверка API, чтение проектов/тарифа/usage и контроль срока действия подключения не выполнены. Наличие Primary в настройках само по себе их не заменяет.

Подтверждение: `evidence/railway-installed-2026-11-06.jpg`.

## Разовость и независимость загрузок

Установка плагина и актуальность OAuth-сеанса — разные состояния. По документации общего OAuth API Railway access token действует один час; для фонового обновления используются refresh tokens, которые запрашиваются с offline_access и prompt=consent. Это объясняет механизм, но не устанавливает причину конкретных отключений плагина Марка через 2–3 часа. Настройки и серверная реализация refresh у установленного ChatGPT plugin не проверены. Обещать «подключить один раз и навсегда» нельзя.

Railway plugin относится к администрированию платформы. Проектируемая передача файлов должна идти Work → собственный HTTPS n8n → GitHub. Она не должна вызывать Railway plugin при каждой загрузке. Потеря авторизации плагина управления сама по себе не останавливает уже развёрнутый сервис. Отдельно проверить срок/обновление OAuth подключения ChatGPT → n8n; оно не тождественно Railway OAuth.

Источники:
- https://docs.railway.com/ai/chatgpt-plugin
- https://docs.railway.com/integrations/oauth/login-and-tokens

Страница Railway Agent Connectors описывает подключения внешних инструментов ВНУТРИ Railway Agent и прямо отличает их от Railway plugin внутри ChatGPT. Её раздел про отсутствие refresh tokens у отдельных внешних серверов не является доказательством устройства нашего ChatGPT plugin.

## Что означает Railway template

Railway Templates — каталог готовых конфигураций развёртывания. Их публикуют Railway и участники сообщества. Шаблон задаёт источники сервисов (например, Docker image), переменные, порт/проверку готовности и диски. Это не обязательно отдельная разработанная программа и не гарантия открытой лицензии: каталог поддерживает и закрытые образы.

Точно проверенные карточки:

| Карточка | Автор в карточке | Источник программы | Состав |
|---|---|---|---|
| https://railway.com/deploy/n8n-10 | zer0person | официальный n8nio/n8n:stable | Один n8n, SQLite, volume /home/node/.n8n |
| https://railway.com/deploy/n8n-7 | darseen | n8nio/n8n:2.42.6 в текущем списке компонентов | Один n8n Lite/SQLite и volume |

У n8n-7 в тексте описания указана другая версия (2.40.7), чем в списке компонентов. Это подтверждает необходимость сверять реальную конфигурацию и закреплять версию, а не считать текст карточки проверенным deployment.

Оба примера используют готовый официальный n8n; отдельного авторского репозитория загрузчика GitHub в этих карточках не показано. Сам workflow загрузки, manifest, retry, один commit/push и проверка байтов туда не входят. Их нужно настроить готовыми n8n nodes с необходимой логикой проверки и журнала.

Корректнее говорить об открытых исходниках/fair-code, не обещая неограниченную MIT-подобную лицензию. Источник: https://github.com/n8n-io/n8n/blob/master/LICENSE.md .

Мы можем использовать официальный image и сохранить собственную проверенную конфигурацию Railway в текущем репозитории. Это конфигурация готового продукта, не написание n8n или нового HTTP/Git загрузчика с нуля. Конкретный template пока не развёрнут.
