## Последовательность и критерии

1. **Закрепить текущий кандидат**: source SHA, export hash, n8n version, deployment ID, схема постоянного журнала, действующий лимит/таймер и ответственный. Сохранить рабочую точку восстановления; не продлевать чужой пилот автоматически.
2. **Сопоставимый nominal test**: воспроизвести benchmark_fixture.py salt 202611061621, 100 файлов / 30,000,000 bytes. Загрузить те же bytes через n8n. Подтвердить один commit, удалённый ref, все 100 SHA-256 и отсутствие посторонних изменений. Сравнивать до remote confirmation, проверку скачиванием отдельно. Повторить 3 пары с новыми corpus, менять порядок маршрутов и отметить clone/cache/region/concurrency. Один текущий direct run — предварительная точка, не статистика.
3. **Повтор завершённой операции**: тот же ID и тот же manifest возвращают прежний SHA без нового коммита. Тот же ID с изменённым manifest — явный конфликт и ноль новых эффектов.
4. **Потеря ответа**: разорвать ответ после подтверждённого remote push; повтор возвращает исходный SHA по durable journal/marker. Не считать сетевую ошибку доказательством отсутствия push.
5. **Аварийные границы**: interrupt до commit, после commit до push, после push до journal/receipt. После restart восстановление сохраняет исходный ID/manifest/SHA; не создаёт второй commit и не теряет подтверждённый результат. Если исход не установлен, безопасная остановка и проверка remote history.
6. **Одновременные запросы и конфликты**: два комплекта в одну ветку; повторы одного ID; новый сторонний remote commit между fetch и push. Изоляция, без смешивания путей/потерянных изменений/force push; no-change имеет явное проверенное поведение.
7. **Авторизация**: token expiry/refresh при длительной работе, отзыв/ошибка прав; узкий scope разрешённого назначения. Отдельный новый Work, управляемый с Android, выполняет upload без копирования секрета в переписку. Публичная инструкция и All repositories у GitHub App не заменяют этого теста.
8. **Валидация**: фактический размер bytes и общий лимит, mismatch SHA-256, отсутствующий/повторный field, дубликаты Unicode paths, file/dir конфликт, traversal/symlink, .git, пути с запятой/кавычками. В исходном пилотном export bytes лимит суммировался по manifest, а pathsToAdd соединялся запятой; это требует отдельной проверки/исправления до широкого назначения.
9. **Ресурсы и восстановление**: повтор нескольких комплектов, disk retention/очистка без потери journal и UNKNOWN, backup SQLite и encryption key, восстановление receipt после рестарта. Исторически диск достигал ~0.743/1GB; метрики пилота не являются billing. Не создавать инфраструктуру/подписки для отчётности.
10. **Окончательная приёмка**: все критерии с exact candidate/deployment/result URLs, успешные/общие случаи; исправить устаревшие README/RUNBOOK указатели, только затем объявлять default route и устанавливать правило персонализации. Старый рабочий маршрут сохраняется до этого.
