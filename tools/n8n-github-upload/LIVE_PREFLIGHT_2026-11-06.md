## Конкретный предлагаемый пилот

Точный план сохранён как `railway-pilot-plan.json`, статус PROPOSED_NOT_APPLIED.

- Тот же существующий workspace; отдельный приватный проект `n8n-github-upload` предлагается для самостоятельного учёта расходов.
- Один service `n8n-upload`, официальный закреплённый image n8n, SQLite, один volume 1024 MB в `/data`.
- Предел RAM 1 GB и CPU 0.5 vCPU, одна replica. Это стартовые ограничения, не измеренное потребление n8n.
- Первая живая проверка — защищённый бинарный roundtrip обычного Work → n8n с SHA-256. GitHub credentials и полный batch-процесс на этом этапе ещё не нужны.
- Предлагаемый бюджет первоначального этапа — **до $1 дополнительного расхода**, до двух часов compute. По ставкам из текущего кабинета два часа при полном использовании этих пределов — около $0.056 compute; бюджет оставляет запас на старт, сеть и диск.
- После ограниченного теста вычисления должны быть остановлены до следующего решения. Сохранённый 1 GB volume продолжает тарифицироваться по использованному месту; верхний ориентир около $0.16/месяц при заполненном томе. Способ ограничения времени и остановки нужно настроить и проверить при запуске, это пока не применённый автоматический лимит.
- Новая подписка Railway/n8n, PostgreSQL, Redis, Railway Agent и LLM не требуются.

Проверка стоимости и необходимости выполнена. До явного решения владельца о дополнительном расходе service/volume не создавались. Это последняя финансовая граница перед созданием реального n8n, а не просьба ещё раз разрешить чтение или установку плагина.
