# Обращение по Railway Deploy передано в поддержку OpenAI

07.11.2026, 12:56 МСК. Задача: https://github.com/markmalina/automations/issues/9
Регламент: https://github.com/markmalina/ai/blob/main/WORK-RULES.md

## Подтверждённый результат

По прямому поручению Марка отправлен запрос через официальный Help Center https://help.openai.com/ru-ru.
Вход выполнен в выбранную владельцем существующую учётную запись.
Отправлены факты отказа исходного railway_accept_deploy, проверенный режим ask_before_writes, target/patch IDs и публичные ссылки на доказательства. Секреты не передавались.

После вопросов ИИ поддержки отправлены уточнения: ручной Work, плагин Railway, личный Pro; поверхность исторического вызова и факт показа approval card неизвестны. Запрошена диагностика человеком без повторного Deploy, изменения данных или расширения доступа. На вопрос «передать специалисту?» нажато подтверждение.

В интерфейсе получены:
- «Запрос на эскалацию отправлен».
- «Передано специалисту службы поддержки; вы можете ожидать ответ в ближайшие дни. Ответы также будут отправляться по электронной почте.»

Это подтверждение передачи специалисту, **не устранение отказа**. Номер тикета/отдельная постоянная ссылка на него в видимом подтверждении не показаны. Разговор сохранён в авторизованном Help Center; вкладка оставлена открытой.
Подтверждение: [снимок экрана](../../evidence/openai-support-escalated-20261107.jpg).

ИИ поддержки предлагал при отсутствии approval card отправить встроенный feedback из исходного Work и передать session ID. Это предварительная рекомендация ИИ, не ответ специалиста и не проверенное исправление. Диагностика из исходного чата пока не отправлялась: доступа к его интерфейсу в текущем Work нет.

## Что заблокировано

S1 остаётся BLOCKED: исходный Deploy и зависимая живая приёмка. Новый исходник не установлен; running=1 не подтверждён. Повторных Deploy, смены permissions или новых Railway ресурсов в этом ходе нет.

Ответ поддержки не является обязательным условием для любой работы с проектом. Можно независимо готовить исходники, локальные тесты, инструкцию/helper Work и проверку GitHub readback по закреплённому commit. Реальные upload/replay/restart/OAuth и приёмка последующих спринтов требуют работающего n8n и не подтверждаются offline проверками.

Новые спринты и новый исполнитель в этом ходе не запускались. Автоматического наблюдения за поддержкой или продолжения по событию не создано. Ответ ожидается в Help Center и по email, как указал интерфейс.
