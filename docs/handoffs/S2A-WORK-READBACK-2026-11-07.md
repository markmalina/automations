## Исполнение

Работает отдельный Work-исполнитель markmalina/automations; текущий Work остаётся контроллером. Можно использовать прежний n8n Work, передав ему новое назначение №10. Создание задачи не запускает чат автоматически.

Короткие подэтапы №10:
1. Прочитать задачу и актуальные инструкции/main/comments, проверить отсутствие другого исполнителя, зафиксировать ветку и конкретную недостающую дельту.
2. Добавить небольшой exact-commit verifier поверх существующего клиента: независимые remote bytes, размер и SHA-256, привязка repo/commit/path/manifest, безопасные VERIFIED/MISMATCH/UNAVAILABLE.
3. Проверить локально положительные и отрицательные сценарии с fake transport; отдельно подтвердить доступный реальный read-only путь на существующем публичном файле либо указать точное ограничение. Не подменять доступ к приватным bytes заглушкой.
4. Обновить WORK_CLIENT.md для нового Work, сохранить reviewable PR/точный head/относящиеся CI и отчёт №10; передать на приёмку и остановиться, issue оставить открытой.

Переиспользовать prepare/receive-grant/upload и защищённый stdin/PTY. Реальный программный путь получения bytes через существующее GitHub-подключение должен быть конкретно описан. Не создавать второй постоянный token, uploader или оркестратор. Марк не готовит manifest, не запускает команды и не переносит секреты.
